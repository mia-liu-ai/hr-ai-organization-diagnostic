# AI 组织诊断与行动共识平台

这是一个本地可运行的组织发展诊断 MVP，包含 React 前端、FastAPI 后端和 SQLite 持久化。产品目标是把项目创建、诊断设计、证据收集、AI 专家诊断会、数据洞察、报告和行动计划串成完整闭环。

主流程：

创建项目 → 设置诊断目标 → 配置组织能力维度 → 生成或编辑诊断假设 → 生成胜任力模型 → 生成综合问卷 → 员工填写 → 数据洞察 → AI 专家诊断会 → 生成报告 → 制定行动计划 → 后续复盘

## 角色与演示账号

系统只面向两个角色：

- 管理员：负责创建项目、配置诊断、生成问卷、查看洞察、运行 AI 专家诊断会、生成报告和行动计划。
- 员工：负责查看说明、完成问卷、参与 360 评审、提交开放反馈和查看必要记录。

推荐演示账号：

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 管理员 | `admin` | `admin123` |
| 员工 | `employee` | `employee123` |

旧本地数据库中的历史演示账号会继续兼容为管理员或员工，避免已有数据无法登录。新的页面、文档和权限判断统一使用“管理员 / 员工”。

## 本地启动

安装依赖：

```bash
npm install
```

启动前端：

```bash
npm run dev
```

启动后端：

```bash
npm run dev:backend
```

构建检查：

```bash
npm run build
```

后端运行后可检查：

- `http://127.0.0.1:8000/docs`
- `http://127.0.0.1:8000/api/health`

## 环境变量

复制 `.env.example` 为 `.env` 后按需配置。

SQLite 默认会写入后端目录下的本地数据库文件。也可以使用：

```bash
DATABASE_URL=sqlite:///./hr360.sqlite3
```

兼容旧配置：

```bash
HR360_DB_PATH=C:\absolute\path\hr360.sqlite3
```

## DeepSeek 与统一 AI Provider

系统通过统一 AI client 调用模型。未配置模型密钥时，后端不会崩溃，AI 生成功能会返回友好提示：

“当前未配置 AI 模型，无法生成内容，请管理员在系统设置中配置模型。”

DeepSeek 配置：

```bash
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=your_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

OpenAI-compatible 配置：

```bash
AI_PROVIDER=openai-compatible
AI_API_KEY=your_api_key
AI_BASE_URL=https://example.com/v1
AI_MODEL=your-model
```

本地占位模式：

```bash
AI_PROVIDER=local
```

不要把 API key 写入代码或提交到仓库。

## 产品模块

- 首页：展示管理员使用向导或员工信任说明。
- 项目中心：创建、查看、编辑、删除、切换项目。
- 诊断设计：设置诊断目标、组织能力维度、诊断假设、胜任力模型和人才画像。
- 证据收集：生成综合问卷，管理问卷中心、360 评审和员工反馈。
- AI 专家诊断会：多专家结构化分析当前项目证据，输出共识、分歧、置信度和行动建议。
- 数据洞察：查看项目维度、问卷、反馈和诊断数据。
- 报告与行动：生成诊断报告、行动计划和复盘追踪。
- 设置：配置模型和系统参数。

## 问卷生成逻辑

问卷不是独立工具，而是证据收集方案的一部分。

- 诊断假设回答：“当前组织可能出了什么问题？”
- 组织能力维度回答：“我们从哪些组织能力角度观察问题？”
- 胜任力模型回答：“解决这些组织问题，需要员工具备哪些能力、行为和管理方式？”
- 问卷生成回答：“我们如何收集证据，验证这些假设和能力差距？”

一份综合问卷可以包含四类问题：

- 组织诊断问题
- 胜任力模型问题
- 360 评审问题
- 开放反馈问题

问卷保存后进入问卷中心，列表、详情和统计都按当前项目过滤。

## 数据隔离和持久化

所有项目相关数据必须绑定 `project_id`，包括组织能力维度、诊断假设、胜任力模型、人才画像、问卷、问卷问题、问卷回复、360 数据、员工反馈、AI 专家诊断会、报告和行动计划。

后端启动不会清空数据库。演示初始化只补齐缺失数据，不覆盖用户创建的项目和业务数据。后续企业部署建议迁移到 PostgreSQL，并增加正式迁移工具。

## 手动验收建议

1. 用管理员账号登录，确认首页出现 5 步使用向导。
2. 创建项目 `111`，编辑项目名称、诊断场景和目标。
3. 创建项目 `222`，确认项目 `111` 仍存在。
4. 在项目 `111` 中新增、编辑、删除组织能力维度，并恢复默认八大维度。
5. 在项目 `111` 中新增、编辑、删除诊断假设，确认顶部没有误导性的全局删除按钮。
6. 生成或编辑胜任力模型，打开详情。
7. 生成综合问卷，保存后到问卷中心查看问题来源和题型。
8. 切换到项目 `222`，确认看不到项目 `111` 的维度、假设、问卷和诊断会结果。
9. 打开 AI 专家诊断会，确认专家角色、输入证据、诊断流程和结果结构都能展示。
10. 用员工账号登录，确认只看到员工任务、填写说明、问卷、360 评审、员工反馈和完成记录。
